# Desktop call controls and screen indicators

The native host provides an app-styled tray menu, retained mention overflow, and screen-share drawing. The drawing-startup repair resolves the helper from app.asar.unpacked in a packaged release; spawn cannot execute a path inside app.asar. Shared JavaScript still owns call state and actions; the native tray never creates a second call session. The tray validates room/session identity before returning to a call, muting, changing deafen, starting/stopping a screen or camera, toggling the roster overlay, or leaving. The idle tray has no background-running subtitle. Return, Open and Quit use centered SVG icons rather than font glyphs with baseline-dependent placement.

`rings.cjs` keeps the latest mentions visible for their existing three-second lifetime. Mentions pushed out of the visible stack become an **+N earlier mentions** row, retained until explicitly opened/dismissed, their room becomes visible, notifications are disabled, or the application document/session closes. Each row retains its original room and exact message key.

## Screen drawing pipeline

1. After a screen capture is committed, shared code calls `chatDesktopDrawing.setSource({active:true, sourceId, shareId, roomId, sessionId})`. The host requires an active sharing call with matching room/session, enabled call overlay and a known Electron capture source. Turning off the call overlay immediately stops the helper and removes its local window; shared code clears outgoing marks. Turning it back on activates the same current source without restarting screen sharing. Racing activations while disabled are handled as a suspended request, not reported as a drawing failure.
2. `drawing.cjs` launches the fixed local `helpers/screen-drawing-helper.exe`, compiled from `scripts/screen-drawing-helper.cs`. Its helperLocation resolver maps packaged app.asar to app.asar.unpacked. Keep helpers/*.exe in asarUnpack and exercise the actual packaged path before releases. No runtime compilation, scripts, command shell, downloads, keyboard log, or persisted drawing content is involved.
3. Hold the middle mouse button and drag inside the selected display/window. The low-level hook consumes middle down and the matching up, so websites never receive the middle-button autoscroll trigger. Movement is recorded and passed through to keep the actual Windows pointer moving; never consume WM_MOUSEMOVE in this global hook. Releasing the button stops drawing; a click never toggles drawing on. No Alt key is used. Normal left/right mouse input, wheel input and keyboard input pass through. Middle gestures started outside the shared source also pass through.
4. The helper paints slim red strokes with black outlines onto a nonactivating, click-through, topmost layered window at 20% opacity. Windows capture exclusion prevents that local preview from being captured a second time. Per-pixel alpha gives 90 ms appearance and 180 ms disappearance; strokes expire three seconds after completing. There is no clear command. Stopping sharing terminates the helper and removes all local marks immediately.
5. Normalized source coordinates arrive through `onStroke` as `{shareId,sourceId,id,phase,points,at}`. The shared compositor draws the marks at full opacity into the ordinary outgoing video track, so existing viewers receive them and their normal zoom/layout applies. Window coordinates use DWM extended frame bounds; display coordinates use Electron's DIP-to-native-pixel conversion. Display resolution, orientation, scale or topology changes restart the input helper with fresh geometry and emit a scoped `reset` event to clear old strokes without interrupting the shared video.
6. Sharing stop, disabled call overlay, document navigation, renderer loss, call exit, and app shutdown all stop input capture. Source switches create a new helper generation and discard late old events. Native startup failures return `false`; unexpected exits emit a scoped `phase:'error'` event. The share continues and shared code shows a drawing-unavailable notice. Startup waits up to 30 seconds to permit normal antivirus inspection without blocking the video call. Never bypass capture exclusion or security protections in order to suppress a real startup error.

The native overlay uses Windows 10 2004+ capture exclusion. Elevated/secure desktops, exclusive fullscreen games, mixed-DPI/multiple-monitor alignment, actual cameras, and sustained performance still need physical-device release testing. No zero-lag or antivirus guarantee is implied by automated coverage. The helper reuses bounded bitmap tiles and performs no frame painting while idle.

## Verification and maintenance

- `node desktop/scripts/build-native-helper.cjs` compiles the fixed updater and drawing helpers. Keep compiled helper filenames and packaging references together.
- `node --test desktop/tests/*.test.cjs tests-release/native-controls.test.cjs` covers state, source/session isolation, cleanup, overflow retention, and unchanged updater behavior.
- `node tests-release/native-menus.browser.cjs` checks the styled tray and clickable overflow renderer.
- `node tests-release/screen-drawing-native.cjs` compiles the test-only reflection harness alongside the production C# source, checks hold/release message handling and middle-button consumption, actual native per-pixel rendering/expiry/resource cleanup, and ordinarily launches the shipping helper to verify readiness and exit on IPC close. It passes private mouse structures and stroke data only into the hidden test harness and never injects user input into Windows or other applications.
- `node desktop/tests/native-update-network.electron.cjs --live` dynamically verifies the current signed public release using the Electron network path; it never installs the downloaded release.
- For the exact shipping EXE, set `CHAT_APP_TEST_PROFILE` to a new absolute isolated directory and `CHAT_APP_NETWORK_SELFTEST=1`, then launch it normally. The fixed diagnostic downloads/verifies only the public `dowsy456/chat-app-desktop` signed feed through the packaged transport, writes `native-network-selftest.json` inside the isolated profile, and exits. It never installs or launches its downloaded EXE. Remove both test variables for normal launches. This path does not enable Node integration, debugging/inspect ports, external scripts, arbitrary URLs, or certificate overrides.

Read the root `NATIVE-UPDATES.md` before any updater change. Preserve the existing public verification key and sign only the exact final EXE with the release owner's matching private key outside the source tree.
